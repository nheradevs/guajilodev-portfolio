01 · What I fix

  1. 01

    Legacy nobody wants to touch

    Java 8 and JSP apps, old .NET, modules only one person understands. I read, I document, and only then do I change anything.

  2. 02

    AI shipped without review

    Copilots writing code nobody reads, prompts with customer data, agents with more permissions than they need. I review what goes in, what comes out, and what gets logged.

  3. 03

    Queries that collapse under history

    Reports that take minutes on huge tables. I measure, split, index, and measure again.

  4. 04

    Friday deploys at 11 p.m.

    No CI/CD, no rollback, no staging environment. I build the path so a deploy stops being an event.

  5. 05

    Systems that don’t talk to each other

    Third-party APIs, the same data in three databases, manual integrations. I define the contract and write it down.

  6. 06

    Teams without shared standards

    Everyone deploys differently and nobody reviews code. I set up reviews, branching, and rules the team can keep.

02 · Applied AI

  1. 01

    Models inside the workflow

    I integrate models from different providers via API into internal tools the team opens every day.

    Limit: if the task doesn’t repeat, it doesn’t justify a model.

  2. 02

    Agents with scoped tools

    Clear permissions, defined scope, and a log of what they do.

    Risk: an agent without limits is an incident waiting its turn.

  3. 03

    MCP servers

    I connect models to in-house tools and data using MCP (Model Context Protocol), with the minimum access the task needs.

    Limit: what the agent can’t read, it can’t leak.

  4. 04

    Auditing generated code

    I read what the model writes before it ships: input validation, contracts, error handling, dependencies, and tests.

    Risk: fast isn’t the same as correct.

  5. 05

    Knowing when not to use it

    A model won’t fix a missing index, a badly designed data model, or a process nobody defined.

    Limit: when the answer is code and not AI, I say so.

03 · How I work

  1. 01

    Business first

    I don’t touch a line until I know what the system does and who uses it.

  2. 02

    Small, verifiable changes

    One thing at a time, with tests where possible. If the code came from a model, someone read it before it merged.
